# Алгоритм подбора музыки в Nocturne

Nocturne работает только с SoundCloud и без ключа API. Поиска по всему каталогу SoundCloud нет, поэтому рекомендации строятся из двух источников:

1. **Ваша библиотека.** Импортированные плейлисты, лайки, история прослушиваний.
2. **Находки через исполнителей.** Лайки и новые треки исполнителей, которых вы слушаете. Их отдаёт официальный встраиваемый плеер SoundCloud (`users/ID/favorites` и `users/ID`).

Главная идея: исполнитель, которого вы любите, сам лайкает похожую музыку. Его лайки становятся кандидатами, а ваш профиль вкуса отбирает из них лучшее.

```
 ваши действия ──► профиль вкуса ──► исполнители-«семена» ──► их лайки и треки
 (лайк, пропуск,     (веса признаков)    (кого вы реально         (кандидаты, кэш 12 ч)
  дослушал)                              слушаете)                      │
                                                                        ▼
            главная: «Для тебя», «Рекомендации»  ◄──  фильтры ─► ранжирование ─► разнообразие
            автомикс, настроения
```

## 1. Профиль вкуса

Каждый трек описывается **признаками**:
- `artist:<исполнитель>`;
- `genre:<жанр>`;
- до 6 тегов `tag:<тег>`.

Каждое действие добавляет **сигнал** ко всем признакам трека:

| Действие | Сигнал |
|---|---|
| Дослушал до конца | +1 |
| Лайк | +3 |
| Снял лайк | −3 |
| Пропустил в первые 30 секунд | −1 |
| «Не рекомендовать трек» | −4 |

**Затухание.** Вес признака уменьшается вдвое каждые 30 дней (`HALF_LIFE_DAYS`). Старые вкусы постепенно забываются, свежие весят больше. Профиль хранится только на телефоне.

## 2. Оценка трека

```
вкус      = (сумма весов признаков трека) / √(число признаков)
новизна   = случайное число от 0 до 1.2      — чтобы выдача не застывала
штраф     = 3, если трек играл среди последних 30
оценка    = вкус + новизна − штраф
```

Пока профиль пуст (первый запуск), оценка складывается только из новизны и штрафа. Получается перемешанная библиотека.

## 3. Исполнители-«семена»

Чьи лайки и треки загружать. Вес исполнителя складывается так:

| Сигнал | Вклад |
|---|---|
| Каждый его трек в избранном | +2 |
| Каждое прослушивание среди последних 120 | +1 |
| Каждый трек в импортированных плейлистах | +0.3 |
| Вес `artist:` в профиле вкуса | ×3 |

- **Исключаются** скрытые исполнители («Не рекомендовать <исполнитель>») и те, у кого вес в профиле ниже −1 (часто пропускаете).
- Из **12 лучших** случайно, пропорционально весу, берутся **5** (`SEEDS`). Поэтому подборки меняются от обновления к обновлению и не крутятся вокруг одного исполнителя.
- Нужен ID исполнителя в SoundCloud. Он есть у треков, импортированных через плейлисты и профиль, а у одиночных треков появляется после первого прослушивания.

## 4. Кандидаты и кэш

Для каждого семени загружаются его **лайки** и **свои треки**, по 60 штук каждого (`PER_LIST`). Результат кэшируется на **12 часов** (`CACHE_TTL`). Исполнители, которых не было среди семян 3,5 дня (7 × TTL), удаляются из кэша.

Главная сначала мгновенно собирается из кэша, а затем по одному дозагружаются устаревшие исполнители, и разделы обновляются по мере загрузки.

## 5. Фильтры

Трек в рекомендации не попадает, если:
- он не из SoundCloud (остатки старых версий);
- вы нажали «Не рекомендовать трек» или скрыли исполнителя;
- вес исполнителя в профиле ниже −1.5;
- SoundCloud не отдал название трека.

Разделы «новинок» и «Если нравится» дополнительно исключают то, что уже есть в библиотеке.

## 6. Разделы главной

| Раздел | Откуда | Правила |
|---|---|---|
| **Для тебя** | 70% новое + 30% «забытое» | 30 треков, не больше 2 треков одного исполнителя, не больше 2 подряд |
| **Новое от твоих артистов** | свои треки семян, свежие сверху | не больше 3 треков одного исполнителя, 15 треков |
| **Давно не слушал** | библиотека минус последние 60 прослушиваний | по оценке, не больше 2 треков одного исполнителя |

## 7. Рекомендованные плейлисты

Собираются по приоритету. **Каждый трек попадает только в один плейлист**, в каждом не больше 2 треков одного исполнителя. Подборка показывается, если в ней набралось хотя бы 5 треков.

0. **Похожие на X** (метка Deezer): популярные треки исполнителей, которых Deezer считает похожими на X, до 20 треков. См. раздел 8a.
1. **Если нравится X:** лайки исполнителя X, кроме его собственных треков, до 15 треков.
2. **Настроения** («Потерянный сон», «Вечная осень», «Психоделия 2000-х», …): треки, чьи жанр и теги совпадают с тегами микса из `moods.ts`.
3. **Жанровые миксы:** 5 самых частых жанров среди кандидатов и библиотеки.
4. **Открытия:** лучшее из новых треков. На главной стоит первым.
5. **Новинки:** свежие треки семян.
6. **Забытое:** давно не игравшее из библиотеки.

## 8. Автомикс

Когда в очереди остаётся 3 трека или меньше, `recommend()` добавляет ещё 15. Кандидаты — библиотека и все находки. К ним применяются те же фильтры и оценка, и не больше 2 треков одного исполнителя подряд.

**Настроение** — это тот же `recommend()`, но с тегами выбранного настроения: берутся только треки с подходящими жанрами и тегами.

## 8a. Deezer: похожие исполнители

Отдельный модуль [src/recommend/deezer/](../src/recommend/deezer/). Deezer знает, какие исполнители похожи друг на друга: эти связи построены по прослушиваниям миллионов людей. Этого и не хватает рекомендациям «по лайкам исполнителя». Музыка при этом по-прежнему играет из SoundCloud.

| Файл | Что делает |
|---|---|
| `api.ts` | Клиент публичного API Deezer, ключ не нужен. Работает через JSONP: Deezer не отдаёт CORS-заголовок, поэтому обычный `fetch` из браузера блокируется. |
| `match.ts` | Ищет исполнителя Deezer на SoundCloud (см. ниже) |
| `similar.ts` | Связывает шаги: семя → похожие по Deezer → профили SoundCloud. Кэш на 3 дня |
| `index.ts` | Точка входа модуля |

**Конвейер** (`deezerStep` в discovery.ts, после загрузки семян):

```
3 главных семени ──► Deezer: поиск исполнителя (точное имя, больше всего фанатов)
                    ──► Deezer: /artist/{id}/related (14 похожих)
                    ──► поиск каждого на SoundCloud, до 6 найденных
                    ──► до 4 на семя: загрузка их треков (без лайков), по 2 параллельно
                    ──► 10 самых популярных песен каждого (по числу прослушиваний)
                    ──► подборка «Похожие на X»: до 20 треков, не больше 2 от исполнителя
```

**Как исполнитель Deezer находится на SoundCloud** (поиска SoundCloud без API нет):
1. Сначала ищем в вашей библиотеке: если у трека этого исполнителя уже есть ID SoundCloud, берём его.
2. Иначе угадываем ник для `soundcloud.com/<ник>`: имя слитно, через дефис, через подчёркивание, `+official`, `+music`. Кириллица транслитерируется: «Три дня дождя» → `tri-dnya-dozhdya`.
3. Каждый вариант проверяем через официальный oEmbed и **сверяем имя профиля** с именем исполнителя. Так отсекаются чужие аккаунты: Flux Pavilion ≠ «BitRatOfficial».
4. Результат кэшируется: найденные на 14 дней, ненайденные на 3 дня.

В проверке нашлись 28 из 30 похожих исполнителей, включая русскоязычных.

**Фильтр «не песня»:** подкасты, радиошоу, интервью, сырые записи, треки короче 1 минуты и длиннее 10 минут исключаются.

**Как выключить:** «Профиль → Похожие исполнители». Тогда шаг Deezer пропускается.

**Ограничения:**
- Профиль по нику находится не у всех. Иногда находится фан-аккаунт с тем же именем.
- JSONP означает, что код ответа Deezer выполняется в приложении. Для личного приложения это допустимо, а для публичного стоило бы проксировать запросы.
- Лимит Deezer: 50 запросов за 5 секунд. С кэшем он не достигается.

## 9. Ограничения без API SoundCloud

- Встраиваемый плеер отдаёт только **последние ~20 лайков** пользователя и первую страницу его треков.
- Нет «похожих треков», станций, чартов и поиска по всему SoundCloud. Поэтому качество рекомендаций зависит от того, сколько вы импортировали и сколько слушаете.
- С подпиской Artist Pro можно получить ключ API (прокси уже готов в `worker/`) и добавить настоящий поиск и похожие треки.

## 10. Как настраивать

| Константа | Файл | Что меняет |
|---|---|---|
| `SIGNAL` | profile.ts | сила реакции на лайк, пропуск, дослушивание |
| `HALF_LIFE_DAYS` | profile.ts | как быстро забываются старые вкусы |
| `novelty` (1.2) | recommend.ts | сколько случайности в выдаче |
| `SEEDS`, топ-12 | discovery.ts | сколько исполнителей опрашивать и насколько разнообразно |
| `PER_LIST`, `CACHE_TTL` | discovery.ts | объём кандидатов и частота обновления |
| `capArtists(…, 2)`, `MIN` | discovery.ts | разнообразие внутри подборки и её минимальный размер |
| `MOODS`, `MIXES` | moods.ts | настроения и их теги |
